Can Machine Learning Predict Human Migration Better?

This post reviews Robinson and Dilkina’s (2018) study on using machine learning to predict human migration. I focus on how the authors build the prediction models, deal with unusual migration data, and compare machine learning with traditional migration models.

1. Research Context

Why Study Human Migration?

Human migration prediction is useful for population planning, infrastructure, labor markets, disease spread, and changes in international trade.

Background and Research Gap

Recent research focuses on human commuting flows instead of human migration. Traditional mobility models mainly rely on population and distance, while the radiation model also considers intervening opportunities.

Gravity/radiation models have fixed mathematical forms, so they are interpretable but may miss complex nonlinear relationships.

At first, I thought a linear relationship meant that one variable directly causes an outcome. However, here it simply means that the effect of a variable is assumed to follow a relatively fixed mathematical relationship, while ML models can capture more complex nonlinear patterns.

Research Objective

The paper does not state explicit research questions. However, its main objective is to examine whether machine learning models can predict human migration more accurately than traditional gravity and radiation models.

Proposed Approach

Use XGBoost and ANN to directly predict the number of migrants moving from an origin zone to a destination zone using features of the origin, features of the destination, and the between-zone features.

2. Data

USA Migration dataset

The dataset covers yearly intra-country migration among 3,106 U.S. counties from 2004 to 2014 using IRS Tax-Stats data.

The authors supplement the migration data with seven per-county features, taken from U.S. Census estimates and calculated using Census TIGER line maps of U.S. county boundaries:

  • population
  • land area
  • population density
  • median household income
  • county water area
  • whether the county is coastal
  • number of neighboring counties

They also add between-county features based on the radiation model’s idea of intervening opportunities, including distance, intervening population, intervening land area, intervening number of counties, intervening population density, and intervening median income.

Global Migration dataset

The dataset contains decadal inter-country migration flows among 207 countries using the World Bank Global Bilateral Migration Database. It includes five timesteps, one every 10 years from 1960 to 2000.

The authors supplement the migration data with five per-country features:

  • population
  • population density
  • population growth
  • agricultural emissions
  • land area

These features come from the World Bank World Development Indicators.

They also include three between-country features:

  • distance
  • intervening population
  • intervening land area

These between-country features describe the relationship between the origin and destination countries and are used as additional inputs for predicting migration flows.

Major characteristics of the data

Each observation is one origin–destination pair. Input includes origin features, destination features, and between-zone features. The target is the number of migrants.

Important issue with the dataset

Data are highly zero-inflated. Most pairs have zero migration, especially in the U.S. dataset. (This means that if we don’t solve this issue, just saying “0 migrating” without any study will be correct 99%. No meaning of analyzing!)

Pre-processing

The authors keep all nonzero migration samples but randomly sample only a portion of the zero-migration samples during training using the downsampling parameter k. The full datasets are still used for validation and testing.

3. Method

Traditional models

Gravity/radiation models first estimate total leaving migrants using a production function, then distribute them across destinations.

I initially thought the production function was the migration model itself, but it is simply a step that estimates how many people leave an origin zone in total before the traditional model distributes them across destinations.

Machine Learning Approach

XGBoost/ANN directly predict the number moving from zone i to zone j, without needing the production function.

The word “directly” confused me at first because it sounded like the model simply guesses the migration number. In fact, it learns a relationship from training data between the input features and the actual migration flow, and then uses that learned relationship to predict.

XGBoost (Extreme Gradient Boosting regression)

Many decision trees are built sequentially. Later trees correct errors left by earlier trees.

ANN (Artificial Neural network model)

Features pass through dense layers with ReLU. ReLU turns negative values into zero and keeps positive values unchanged.

The model repeatedly updates weights to reduce loss.

I initially could not understand what an epoch meant. I learned that the model updates its weights after each mini-batch, so every new epoch starts with an already updated model.

Custom loss

The authors develop a CPC-based loss because the migration data are highly zero-inflated and long-tailed, and CPC is one of their key evaluation metrics.

The goal is to make predicted migration overlap more with actual migration.

I first understood CPC only as an evaluation metric, so I was confused when it appeared again as a loss function. The authors adapt the same idea of overlap between actual and predicted migration so that the ANN can learn toward predictions with higher overlap.

Hyperparameter tuning

  • XGBoost: maximum tree depth, number of estimators, learning rate
  • ANN: loss function, number of layers, layer width, number of training epochs, mini-batch size

They use randomized grid search to test different combinations and select the combination with the best validation CPC.

4. Validation

Three consecutive timesteps are used as the training, validation, and test sets, respectively. (past timestep = training → next timestep = validation → next timestep = test.)

Year itself is not used as an input feature. The order is kept because the goal is future prediction.

This part confused me the most. Since year itself is not used as an input feature, I first wondered why the years still had to stay in order. I eventually understood that the chronological order is preserved to imitate real forecasting: the model learns from an earlier period and is evaluated on later periods.

  • They repeat this over multiple consecutive time periods and average test results.
  • Metrics to assess models: CPC, CPCd, RMSE, R2, incoming MAE, incoming R2.
    • CPC = how much predicted flows overlap with actual flows
    • CPCd = whether travel-distance patterns match
    • RMSE = how large prediction errors are
    • R2 = how well the model performs relative to simply predicting the mean
    • Incoming metrics = how well total migrants entering each region are predicted

5. Analysis: Results + Interpretation

Overall, the ML models outperform the traditional gravity and radiation models.

The results suggest that features beyond those used by traditional models are needed for more accurate migration prediction.

For the extended-feature results, ML models without a production function generally performed better than the same models with a production function.

XGBoost was better on most per-link metrics, while ANN was better at predicting total incoming migrants.

I initially confused these two types of evaluation: per-link metrics evaluate each origin–destination pair separately, while incoming-migrant metrics add together all flows entering the same destination.

Feature importance

U.S.: The # of intervening counties was the most important feature.

Global: Population growth of the origin country was the most important feature on average, but its importance varied across timesteps.

Interpretation

Flexible ML models can combine more features and capture nonlinear relationships that fixed analytical models may miss.

6. Reflection

What I learned

One of the main things I learned from this paper is that traditional models are easier to interpret, while ML can capture more complex nonlinear relationships. I also learned why data imbalance and loss functions matter and gained a better understanding of train-validation-test splitting. More broadly, the paper showed me that model performance depends not only on the model itself, but also on preprocessing, loss-function design, and validation.

The most difficult parts for me were understanding the production function, what “direct prediction” actually means, and why the data were split chronologically even though year itself was not an input feature. I also initially struggled with concepts such as nonlinear relationships, data imbalance, and the CPC-based loss function. After going through the paper more carefully, I understood that these concepts are all connected to the same goal: designing a model that can learn complex migration patterns and evaluate whether those patterns can predict future migration.

What I still want to know

I still want to know how the results would change if long-term temporal trends were explicitly included in the model. I also want to better understand why the CPC-based loss performed better than MSE and how much predictive accuracy is gained at the cost of interpretability.
